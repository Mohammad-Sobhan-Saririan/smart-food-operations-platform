# Architecture

## Runtime components

- **Frontend:** Next.js App Router application with Zustand state, responsive role-aware views, Recharts reporting UI, and optional Firebase messaging.
- **Backend:** Express API with route/controller/service separation, cookie-based JWT authentication, role/permission middleware, SQLite persistence, SSE, and optional integrations.
- **Database:** SQLite schema initialized from `Backend/db/db.js`. Public demo data is generated by `Backend/seed/seed.js`.

## Authentication modes

`AUTH_MODE=local` is the default. Passwords are bcrypt hashes stored only for synthetic/local users.

`AUTH_MODE=ldap` enables the optional Active Directory adapter. User credentials are used only for the bind/authentication operation and are never persisted. The application stores only selected profile attributes and issues its own JWT session after successful LDAP authentication.

## Cafe order boundary

The order API ignores client-supplied identity and prices. It resolves the session user, loads canonical products, calculates the total, validates stock/limits, applies optional credit, updates inventory, and inserts the order in a transaction. `clientRequestId` is unique to provide idempotent retries.

## Restaurant domain

The restaurant subsystem models companies/locations, meal types, dishes, weekly menus, daily options, entitlement groups, reservations, statuses, delegation, and signed delivery locks.

Delegation is owner/delegate based with numeric priority. Reservation writes record the acting proxy and the priority used, allowing the workflow to prevent lower-priority overwrites.

## Real-time behavior

SSE is used for per-user order events. The current service stores active response objects in memory, so multiple backend replicas would require a shared event bus for complete fan-out.

## Reporting

Restaurant operational reports are deterministic aggregations over SQLite.

The optional LLM reporting path receives schema metadata only and may generate a read-only query. Both direct SQL and generated SQL pass through `security/readOnlySql.js` before execution.

## Optional integrations

The public default has no external runtime dependency:

- LDAP: off
- Firebase: off
- LLM: off

Core cafe, reservation, delegation, reporting and SSE workflows remain local.
